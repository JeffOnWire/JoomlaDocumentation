This article defines the required structure and tutorial-specific style guidance for tutorial articles. For general documentation formatting rules that apply across all article types, see the Documentation Style Guide for Contributors.

Use British spelling throughout (e.g. customisation, colour, behaviour, organise), consistent with the Joomla platform and its documentation.

Prerequisites

Always an unordered list, and always begins with a link to the Tutorial Introduction. That tutorial covers the type of site to use, how to log in to the frontend and backend, how to view the site, and how to switch between the frontend and backend—individual tutorials don't need to restate any of this. Additional items may reference other tutorials the user should have completed, in this same link format, or state other knowledge, skills, or site-state requirements specific to this tutorial. Every reference to another tutorial includes a brief description of what it provides or assumes—never a bare, undescribed link. E.g. 2 First Steps — covers basics assumed in this tutorial.

  • 1 Tutorial Introduction covers where to run your tutorial, and includes the required frontend/backend login and site-viewing tutorials (1.1, 1.2, 1.3).

Setup

Optional. Any setup work required to prepare for the tutorial. E.g. if the tutorial is to create a complicated menu structure requiring several articles, setup might include creating those articles so they are ready to be used in the tutorial.

Steps

This is the tutorial. The steps the user should follow.

Brief 1-2 sentence introduction (optional), a numbered list of steps, and an optional 1-2 sentence summary.

  1. Steps are concise, directive action statements written in active voice. E.g. view the site; click the link in the Main Menu; observe that an article appears with detailed information.
  2. Direct the user to log in only once per tutorial, as the first step (in Setup if the tutorial has one, otherwise as step 1 of Steps). E.g. Log in to Joomla backend and navigate to the Home Dashboard. Don't repeat this instruction elsewhere in the same tutorial.
  3. When the same action is triggered more than once in a tutorial (e.g. clicking Save & Close to save a form), write Click before it the first time it appears, then drop Click for every later occurrence of that same action. E.g. the first save is "Click Save & Close," every later save in the same tutorial is just "Save & Close."
  4. When the same routine, self-evident action-and-result pair repeats within a tutorial (e.g. clicking New to open a fresh form), state the Result: the first time it appears, then omit it for every later occurrence of that same pair. E.g. the first "Click New" of a given form type is followed by "Result: A new-article form appears," every later "Click New" for that same form type in the same tutorial states no result at all.
  5. On-screen elements the user needs to locate—menu items, fields, components, links—are highlighted in bold (<strong> tags), e.g. In the Administrator Menu, click Content, then Articles.
  6. When directing a user through a series of nested menus, write the path as a single bolded breadcrumb using a right angle bracket (>), surrounded by spaces, to separate each level, rather than spelling out each click individually. E.g. Navigate to Content > Articles. Do not use an arrow (→) or other symbol for this.
  7. A word can be both a field name and an ordinary word, depending on how it's used—bold only applies when it names the on-screen field itself. E.g. in "Author is set to Use Global (Show)," Author is the field being located, so it's bold. In "the author will appear when viewing the article," author refers to who wrote the article, not the field, so it takes no emphasis at all.
  8. Specific values, names, and labels the user should recognise but not interact with—article titles, role names, field values, statuses—are italicized (<em> tags), distinguishing them from clickable UI elements in bold. E.g. the Dogs article; the Editor role; the article status is Unpublished.
  9. Use screenshots to assist users in finding details or controls on the screen, content details, etc.
    • Screenshots appear adjacent to the instructions to which they pertain and left-aligned with the text of the instruction, in their own horizontal space.
    • In a list, the image follows the list item text, separated by a single <br> tag before and after to add a line of white space above and below the image. This spacing works best when the image is the last thing in the list item.

    • Occasionally, a screenshot may instead appear in the tutorial's opening paragraph, before Prerequisites—not to assist with a specific instruction, but to visually establish the detail or setting the tutorial focuses on. Use only as many as needed to establish the concept once; don't repeat the same idea in more than one screenshot.
    • Screenshots appear as either a plain <img> tag or, when captioned, wrapped in <figure>/<figcaption>—this follows directly from Joomla's own image-insert dialog (right-click an image, choose Image): leaving the caption field blank produces an <img> tag, filling it in produces a <figure>. This is a deliberate, accepted inconsistency, not an error to fix—editors without HTML knowledge can only control it through that one checkbox, so don't convert between the two forms to enforce uniformity.
  10. Steps are presented in an ordered (numbered) list.
    • When sub-items are used, they appear as bullets.
  11. When a step involves filling out a form, follow the triggering action with an indented, unordered list of the fields to complete, then return to the numbered list for the next sequential action (e.g., saving the form). Within each field bullet, bold the field name and italicise the field value, in keeping with the bold/italic rules above. If the text after the field name is not the literal value—guidance about what to enter, such as "leave blank," or a pointer to an external source of placeholder text—leave it as plain text instead, since there's nothing on screen for the reader to match against. This applies whether the value is a single word or a full sentence. E.g.
    • Click New to create a new article.
      • Title: Animals
      • Article Text: leave blank or type a few simple words.
    • Save & Close
  12. State the expected result of an action within the same list item as the triggering action, as a separate sentence introduced with a bolded Result: label. E.g. "Click the Articles link. Result: A list of articles appears."
  13. Brief supplementary information that is neither an instruction nor a stated result—an aside, tip, or warning—is added as a separate sentence within the relevant list item, introduced with a bolded label: Note:, Tip:, or Warning:. E.g. "Click Save & Close. Warning: This action cannot be undone."

Substeps

Used for clarity in long tutorials. E.g. a tutorial that creates an article, then a menu item, then a module to contain a menu might be divided up into those substeps.

Brief 1-2 sentence introduction (optional), a numbered list of steps, and an optional 1-2 sentence summary.

  1. The numbered list of steps begins at 1 in each substep.
